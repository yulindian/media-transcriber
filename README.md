# media-transcriber

当前版本 **0.2.0** · [版本记录](CHANGELOG.md)

发一条音视频链接，让 Agent 转录全文、校对分段、整理内容总结，并保存为 Markdown。

支持小宇宙、小红书、抖音、视频号、B站、YouTube，以及本地音视频和媒体直链。获取能力取决于内容权限和平台入口，不能保证每条链接都可下载。

## 最快开始：把这段发给 Agent

复制下面的内容，替换最后一行即可：

```text
请安装并使用这个技能转录音视频：
https://github.com/yulindian/media-transcriber

先阅读仓库 README.md，再读取 SKILL.md，按其中步骤执行。
如果已安装，请复用现有配置和运行环境；如果尚未安装，按 README 初始化。
完成全文转录、说话人标注、逐段校对、标点分段、质量检查、疑点验收和验证导出。
正文前增加总结：单一主题只写一段；播客等多主题内容按话题提供时间轴总结，每段概括实质内容。
保留完整发言，不要改成摘要；不确定的文字或说话人保留疑点。
最后给我本地 Markdown、原稿、纠错记录和字幕文件的路径。

输入：<分享链接或本地文件的绝对路径>
```

**Agent 需要能读写本地文件、执行终端命令，并联网获取媒体和首次下载模型。** 当前安装脚本面向 Windows，语音识别在本机 CPU 运行，无需 GPU，也无需额外配置转录或纠错 API Key。

支持读取 Markdown 指令并执行本地命令的 Agent 可以按此流程使用。Codex 可通过 `$media-transcriber` 调用；其他 Agent 若不支持这个语法，直接读取安装目录的 `SKILL.md` 并执行即可。仅能聊天、无法访问本机文件与终端的 Agent 不能独立运行本技能。

## 已安装：发链接即可

在已加载本技能的 Agent 中发送：

```text
用 media-transcriber 完整转录下面的音视频，校对错字、补标点、
标注说话人并按话意分段，保存到 <输出目录>：
<分享链接或本地文件的绝对路径>
```

在已经明确要转录的同一对话中，后续可以只发链接。任务中断后，用原链接或原任务目录继续，脚本会复用已完成的缓存。

也可以直接粘贴包含链接的完整分享文案。多条输入支持可续跑队列：Agent 会先预览去重结果，再逐项处理，单条失败不阻断其他任务。已知平台的同一作品可复用任务，B站不同分P分别处理。

## 会得到什么

| 文件 | 内容 |
| --- | --- |
| `.md` | 总结与逐字稿；单主题一段总结，多主题按话题列时间轴，正文无时间轴和行内核对标记 |
| `.原始.md` | 未校对的机器识别稿 |
| `.纠错记录.json` | 每次修改的前后文本、理由与依据 |
| `.srt` | 带说话人标签的字幕 |

### 案例一：教程口播整理成自然段

输入是一条操作教程。输出保留完整口播，核对有依据的工具名，并按句意分段。下面的内容经过脱敏和改写，只展示成稿结构，不对应真实作品或测试报告：

```markdown
# AI 工具操作教程（格式示例）

## 内容总结

介绍从商品参考图到成片的制作流程：先保证商品画面一致，再安排镜头和配音，最后检查字幕与衔接并导出。

## 正文

先准备商品参考图，再用即梦生成画面。这里需要保持商品外观一致，避免每张图都变成不同的产品。

画面确认后，再整理镜头顺序和配音。遇到生成效果不稳定的地方，回到对应步骤调整。

最后检查字幕、商品细节和画面衔接，再导出成片。
```

单人校对稿直接分段，不在每段重复标“说话人1”；多人保留说话人标签。阅读稿正文不显示时间轴和“词句待核对”“片段待核对”等编辑标记。音轨定位、原始角色和核对疑点保留在原稿、字幕及纠错记录中，不因隐藏标记而视为已确认。

阅读稿会接回被识别切片拆开的连续词句，在句子结束或话意变化处换段，避免“我”“所以他”各占一段。独立短“嗯、啊、哦”等纯语气应答可省略，原稿和字幕仍完整保留；否定、数字及有意义回答不删。

### 案例二：多人访谈按说话人分段

输入是一段访谈。输出按声音特征区分说话人；短应答或重叠发言的疑点记录在纠错文件中。以下同样是脱敏、改写后的格式示例：

```markdown
# 访谈逐字稿（格式示例）

## 时间轴总结

### 00:00:10–00:12:30｜从需求出发验证方案

讨论为什么开始做这个项目，以及如何找到值得解决的问题。通过先做小版本收集反馈，减少投入大量时间后方向失误的风险。

### 00:12:30–00:26:00｜根据反馈调整下一步

梳理试用反馈中的共同问题，讨论哪些值得优先修改，以及如何安排后续验证。强调先确认变化带来的效果，再决定继续投入的范围。

## 正文

**说话人1**：开始做这个项目时，你最担心的是什么？

**说话人2**：我担心投入很多时间，最后却没有解决真正的问题。所以我们先做了一个可以验证的小版本。

**说话人1**：对，先把最关键的流程走通。

**说话人2**：有了反馈，再决定下一步做什么。
```

说话人编号由声音特征估计，不等于真实姓名。短应答、抢话和背景音乐可能影响归属。不确定的部分保留复核记录；文本校对、人工听审和说话人验证分别记录。

数值、日期、比例和常见单位的改动需要额外的音轨复核记录。导出前必须完成当前版本的质量检查与验收，保留疑点会在成稿中披露。检查通过不代表已逐句听审。

## 从链接到成稿，Agent 会做什么

1. **取得真实音轨。** 识别平台，使用公开入口或已配置的解析服务获取媒体，检查音轨格式、时长和文件完整性。
2. **本地转录与角色估计。** 识别全文和时间戳，按声音特征生成说话人编号。
3. **逐段校对。** 当前 Agent 阅读正文，结合来源标题和上下文修正有依据的错字、补标点、整理自然段。含混词句保留疑点。
4. **质量检查与验收。** 检查碎片、长段和角色归属等候选问题；修正后重新检查，对需要保留的疑点记录原因。
5. **总结、导出并验证。** 单主题撰写一段总结；多主题按实质话题组织时间轴总结，时间来自原始段落。保存四份文件，回读成稿并核对哈希。最终回复应包含本地文件链接、覆盖时长和重要疑点。

| 返回状态 | 已做到哪一步 | 后续还需要什么 |
| --- | --- | --- |
| `audio_ready` | 音轨已取得并验证 | 识别、校对、验收和导出 |
| `review_pending` | 机器识别完成 | 全文校对、验收和导出 |
| `batch_ready` | 批量任务已进入音轨或草稿就绪状态 | 对每项继续后续流程 |
| `complete` / `existing` | 当前验收通过，文件已保存并验证 | 阅读结果中的保留疑点 |
| `failed` / `batch_partial` | 部分步骤或任务失败 | 根据错误分类恢复，其余任务仍可继续 |

`complete` 表示约定的流程与文件检查已完成，不表示逐字或说话人准确率达到 100%。

## 手动安装（Windows）

先准备 Git、uv、FFmpeg（含 `ffprobe`）和 `curl.exe`，在 PowerShell 中运行：

```powershell
# Codex 默认技能目录；其他 Agent 请改成其技能目录或普通工作目录。
$skillDir = Join-Path $env:USERPROFILE '.codex\skills\media-transcriber'
git clone https://github.com/yulindian/media-transcriber.git $skillDir
Set-Location -LiteralPath $skillDir
.\scripts\setup.ps1
```

首次安装会创建 Python 3.12 运行环境、下载模型并生成本地 `config.json`。成稿默认保存到「文档」下的「音视频转录」，可修改 `config.json` 的 `output`，或在调用时指定目录。已有安装先读取其配置，避免覆盖个人设置。

默认单条媒体最多 2 GiB、音轨最多 2 小时，并设有下载、转换和磁盘预算。更长任务可在本机资源允许时调整 `config.json.limits` 后续跑，具体字段见[资源预算](references/operations.md#资源预算与来源隐私)。

安装后，让 Agent 读取该目录的 [SKILL.md](SKILL.md)。它是执行入口；本 README 是安装和使用说明。

## 平台与登录

小宇宙公开单集优先从节目页获取音轨；其他平台按配置使用公开入口、yt-dlp 或匿名解析服务。视频号依赖已配置的解析服务或自定义解析器。

默认不读取浏览器登录态。部分平台会将公开分享链接发送给配置的第三方解析服务，可在 `config.json` 设置 `anonymous_api.enabled=false` 关闭。需要 Cookie 时仅使用用户明确提供的文件。私有、付费或受限内容获取失败时，可改用有权访问的本地文件或媒体直链。

完整获取地址保留本地。导出元数据会移除来源链接中的签名参数和本地文件路径；正文中的原话保持原样。

## Agent 的执行入口

按 [SKILL.md](SKILL.md) 执行以下流程：

```text
获取音轨 → 本地识别与说话人估计 → 分批校对 → 疑点检查与验收 → 内容总结或话题时间轴 → 验证并导出
```

`run` 只生成待校对任务，不会自行完成文字校对。Agent 必须继续执行 `review → apply-edits`，完成全文审阅后执行 `quality → accept-quality → apply-summary → finalize --require-summary`。总结由当前 Agent 基于校对全文撰写，不另行调用模型 API。时间轴按话题组织，不机械等分时间，也不为每句话单列一项；正文或来源更新后需重新生成总结。可疑片段可用 `clip` 提取音轨，或用 `recheck` 局部重识别；候选文字需核实后再修改。旧任务的校对缓存仍可复用，导出时补齐当前版本所需的验收与总结。

获取失败时可用 `prepare` 单独验证音轨；`batch` 提供预览、队列恢复及显式重试。命令的标准输出为 JSON，运行进度写入标准错误。音轨就绪、批量就绪均不代表逐字稿已完成。[批量及错误恢复说明](references/operations.md#批量队列)

- [SKILL.md](SKILL.md)：Agent 应遵循的步骤与交付要求。
- [命令与恢复参考](references/operations.md)：参数、校对 JSON、质量检查、缓存和故障恢复。
- [使用方案](使用方案.md)：常见场景与详细说明。

当前提供 Windows 安装流程；macOS、Linux 和不同 Agent 的原生技能安装方式未逐一验证。

## 常见问题

**是否必须登录平台？** 默认尝试公开内容，不读取浏览器登录态。某些内容或入口可能要求授权；这时可提供有权访问的本地文件、媒体直链，或明确授权的 Cookie 文件。

**为什么已经下载成功，Agent 还在处理？** 下载、识别、校对和导出是不同阶段。只有音轨或机器原稿时，还不能当成已校对全文。长播客通常需要分批识别和审阅。

**任务中断后是否会从头开始？** 相同输入优先恢复原任务，已验证的音轨、识别片段和声纹特征会复用。输入内容或配置变化时，受影响的阶段需要重新处理；不要手工删除任务目录。

**为什么多人稿用说话人编号，没有真实姓名？** 识别声音和确认身份是两件事。已知参与人数可以帮助聚类，但姓名对应仍需证据。短应答、抢话和模仿声线可能造成错分。单人校对稿正文省略编号，直接分段。

**为什么有些错字没有直接改掉？** 无法确认的词不能靠猜。数字、日期、比例和常见单位涉及原意，变化时需要额外复核；没有音轨依据就保留原识别及疑点。

**能否一次处理多条？** 可以。让 Agent 将输入写入私有批量文件，先预览去重结果，再逐项处理。队列失败项不会自动无限重试，可以稍后显式重试；队列就绪后仍要逐项完成校对与导出。

**数据会发到哪里？** 原始音频的识别和声纹计算在本地运行；链接可能按配置交给第三方解析服务。文字校对由当前 Agent 完成，其数据处理方式取决于使用的 Agent 服务。个人配置、媒体、任务缓存及真实成稿不应提交到公开仓库。

**如何更新技能？** 先让 Agent 检查安装目录和未提交改动，保留 `config.json`、模型、任务缓存及成稿。Git 克隆安装可在确认工作区状态后拉取更新；复制安装则同步源码与文档。更新后运行环境诊断，并按新版本要求继续已有任务。

**如何查看或回退版本？** 查看安装目录的 `VERSION` 与 `CHANGELOG.md`。自 0.2.0 起发布提交带 `v版本号` 标签，可让 Agent 在保留个人配置、缓存与输出后切换到已发布版本。不要覆盖未提交的本地修改。
